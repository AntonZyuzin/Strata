# Спайк 3. «Камера-мост» 2D ↔ 3D

> Статус: **готов, ждёт прогона владельца** (2026-10-23). Переход между холстом (Pixi) и звёздной картой (three.js) по [08](../08-view-3d.md) §7: кадр 0 карты совпадает с холстом, первый кадр 3D — за десятки миллисекунд, перелёт 600 мс туда и обратно. Связано: [ADR-0005](../adr/0005-rendering.md), [08](../08-view-3d.md) §7, §8.1, [14](../14-nfr.md) NFR-15, [16](../16-roadmap.md) §3.2, шаг 0.3b, [S2](S2-starmap.md).
>
> Код: [`packages/view3d/src/bridge.ts`](../../packages/view3d/src/bridge.ts) — поза камеры кадра 0 и хронометраж; [`packages/ui/src/proto/map3d.ts`](../../packages/ui/src/proto/map3d.ts) — `M` в прототипе; [`packages/bench/src/bridge.ts`](../../packages/bench/src/bridge.ts) — сценарий `bridge-2d-3d`.

## Кратко

- ✅ **Кадр 0 совпадает с холстом на 100 %**: 0 отличающихся пикселей при критерии ≤ 1 % (M1, DPR 2; в e2e на программном WebGL — тоже ≤ 1 %).
- ✅ **`M` → первый кадр 3D — 17,6 мс** с ожиданием GPU (медиана 5 попыток) при NFR-15 ≤ 100 мс; в прототипе — 29 мс от нажатия.
- Перелёт: 600 мс, работа CPU — 2,1 мс на кадр (положения 22 000 звёзд и 30 000 нитей пишутся каждый кадр). Время кадра на GPU — как у `map-orbit-20k` ([S2](S2-starmap.md)), решение по p95 — за прогоном в сборке.
- 💡 Решение для 08 §7.1: в кадре 0 three.js кладёт на плоскость сети **снимок кадра Pixi**, а не перерисовывает баблы. Так совпадают и подписи, и кромки, и фон, и при любом будущем виде бабла; снимок гаснет за 150 мс, пока звёзды вылетают из плоскости.

## Как устроено

| Шаг | Что происходит | Где |
|---|---|---|
| Заранее | Через 1 с после открытия прототипа воркер считает раскладку пространства (`strata-layout`, WASM), карта строит буферы — кэш 08 §3.5. Изменился граф — пересчёт при следующем `M` | `Map3D.prepare` |
| `M`, кадр 0 | В одной задаче: кадр Pixi (`renderNow`), снимок его буфера в текстуру (`initTexture` — сразу, пока буфер жив), кадр three: камера перпендикулярно плоскости на расстоянии `d = H / (2 · zoom · tan(φ/2))`, φ = 15°, текселы снимка один к одному (`nearest`, без преобразования цвета) | `planePose`, `StarMap.setSnapshot` |
| 0–150 мс | Снимок гаснет; прямые 3D-нити сети проявляются вместо кривых 2D; bloom гаснет вместе со снимком, чтобы не просвечивать сквозь него | `Bridge.frame` |
| 0–600 мс | Камера отъезжает и наклоняется на 25°, FOV 15° → 60°; звёзды сети летят из плоскости на 3D-места с задержкой до 100 мс по удалённости от центра; пространство сдвинуто так, что скопление сети стоит на центре её баблов — звёзды летят недалеко | `Bridge` |
| 400–600 мс | Остальные звёзды и нити проявляются | `setFade` |
| 3D | Тянуть — вращать вокруг сети, колесо — ближе и дальше; `M` — обратно | `Map3D.orbit` |
| `M` обратно | Свежий снимок холста, те же кадры в обратном порядке из любой позы камеры; в конце кадр — ровно холст, после чего снова виден Pixi | `Map3D.to2d` |

Остальное пространство в прототипе — синтетическое, 3 000 нод (ядра ещё нет, [16](../16-roadmap.md) §3.2); текущая сеть — настоящая, 220 нод прототипа. В бенчмарке — 20 000 синтетических нод плюс сеть прототипа.

## Что нашли по дороге

1. **three r186 всегда создаёт контекст с альфой**: параметр `alpha: false` управляет только очисткой. Звёзды пишут альфу покрытия (alpha-to-coverage), и сквозь холст карты просвечивал Pixi. Последний проход кадра теперь всегда ставит альфу 1.
2. **Снимок надо загрузить в той же задаче**, что и кадр Pixi: после показа кадра буфер WebGL-холста пуст. На обратном пути первый кадр снимок не рисует (он ещё прозрачен), поэтому текстура грузится сразу в `setSnapshot`.
3. **WebKit выполняет кадр, отменённый внутри того же цикла `requestAnimationFrame`**: после `destroy` холст рисовал по разрушенной сцене. `CanvasView` теперь проверяет `destroyed` в начале кадра и отключает `ResizeObserver`.
4. Полупрозрачные звёзды вблизи (готово, пауза) показывают мелкий узор покрытия MSAA. Терпимо; если будет мешать — сортировка ближних звёзд вместо alpha-to-coverage.

## Чек-лист владельца

1. Прототип холста → `M` (или «3D» в окне сверху): переход без скачка в первом кадре, сеть вылетает в пространство, остальное проявляется к концу.
2. В 3D: тянуть — вращать, колесо — ближе. `M` — обратно: последний кадр — ровно тот же холст.
3. Окно «Бенчмарк» → строка «Мост 2D ↔ 3D»: «кадр 0» — 0 %, «1-й» — меньше 100 мс.
