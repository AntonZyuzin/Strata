# ADR-0004. Оболочка приложения: десктоп и веб

- Статус: Предложено (до спайка 1 и ответа на B2, [15 §7](../15-architecture.md))
- Дата: 2026-10-14
- Связано: [15-architecture.md](../15-architecture.md) (§1, §2.5, §4.4, §5, §6, §8.6), [14-nfr.md](../14-nfr.md) (§2, §3, §7, §15), [10-storage-sync-collab.md](../10-storage-sync-collab.md) (§4, §5), [11-server-selfhost.md](../11-server-selfhost.md), [16-roadmap.md](../16-roadmap.md) (§4.5, §4.6), [08-view-3d.md](../08-view-3d.md) §8.4, [03-vision.md](../03-vision.md), [ADR-0003](0003-sync-engine.md), [ADR-0005](0005-rendering.md), [ADR-0006](0006-board-engine.md), [ADR-0008](0008-mcp-architecture.md); исследования [R4](../research/R4-app-shell-rendering.md) (главное), [R3](../research/R3-crdt-sync.md), [R5](../research/R5-board-engine.md), [R6](../research/R6-mcp-ai.md)

## Контекст

Требования:
- ✅ B1: приоритет — веб и десктоп; мобильное приложение — опция на потом.
- ✅ J2: совместная работа в реальном времени — нужен свой self-hosted сервер.
- ✅ K1: Claude и Codex работают с графом через MCP. Локальные клиенты запускают MCP-сервер как команду по stdio ([R4](../research/R4-app-shell-rendering.md) §1.4, [ADR-0008](0008-mcp-architecture.md)).
- ✅ N1, ✅ A4: тысячи нод без тормозов, число нод не ограничено. Бюджеты [14](../14-nfr.md): холст N-5k — p95 ≤ 16,7 мс на ноутбуке со встроенной графикой (NFR-01), карта 20 000 звёзд — так же (NFR-12), установщик ≤ 80 МБ (NFR-54).
- ✅ E1: доски — Excalidraw, а он существует только как React-компонент: peer `react` 17–19 ([R4](../research/R4-app-shell-rendering.md) §5).
- Соло-режим не требует сервера и аккаунта ([03](../03-vision.md)); в локальном режиме десктоп не слушает сеть (NFR-81).
- B2 (кто пишет код, есть ли опыт Rust) — без ответа: ❓ Q-15-2.
- ОС владельца неизвестна; референс omarchy.org намекает на Arch + Hyprland под Wayland: ❓ Q-15-1.

Факты, которые ограничивают выбор ([R4](../research/R4-app-shell-rendering.md) §1):
- Tauri 2.12.3 (Apache-2.0 OR MIT) рисует UI системным WebView: WebView2 на Windows, WKWebView на macOS, WebKitGTK на Linux.
- Документация Tauri о Linux: «WebGL2 context creation succeeds even when the result is backed by a software rasterizer or a slow presentation path. There is no error to catch». Строка рендерера замаскирована под «Apple GPU»; на NVIDIA бывают пустое окно, мерцание и падение при ресайзе. Совет самой документации — «give it a non WebGL fallback on Linux».
- WKWebView обновляется только вместе с ОС; частота кадров может быть ограничена 60 Гц даже на ProMotion (не проверено для 2026).
- Electron 44.7.0 (Chromium 152, Node 24.18.1) даёт один движок на всех ОС, но рантайм весит 117–151 МБ, а встроенного автообновления на Linux нет.
- Tauri 3 выбирает рантайм при сборке: wry или CEF (`tauri-runtime-cef` 3.0.0-alpha.5, CEF 152). На 2026-10 это alpha, сроки стабилизации не объявлены.

## Решение

**Десктоп — Tauri 2 с Rust-ядром `strata-core` в процессе приложения. То же ядро работает в self-hosted сервере `strata serve` и за командой `strata mcp`. Интерфейс — одна TypeScript SPA на React 19 + React Compiler; с данными она говорит только через интерфейс `Backend`. На Linux решение действует при условии, что WebKitGTK проходит гейт качества на машине владельца.**

1. **Ядро в трёх ролях** ([15](../15-architecture.md) §1.1, §5.2):

   | Роль | Где живёт `strata-core` | Вход |
   |---|---|---|
   | Десктоп | В процессе Tauri, который первым открыл пространство; лок — `.lock` в папке пространства ([10](../10-storage-sync-collab.md) §3.1) — исключает второго писателя | Команды и каналы Tauri |
   | Сервер | `strata serve` — один бинарник: ядро, авторизация, синхронизация, `/mcp` ([11](../11-server-selfhost.md)); сервер для своих устройств — этап 2 (если так решится Q-04-4), команда — этап 3 ([16](../16-roadmap.md) §4.6) | HTTPS и WSS |
   | MCP (MVP+ 1.1, [16](../16-roadmap.md) §4.5) | `strata mcp` находит ядро по `.lock` пространства и подключается к сокету этого процесса (0600, токен); если окна нет — поднимает `strata core --headless`; при открытии окна headless-ядро передаёт ему лок ([15](../15-architecture.md) §5.2). Сокет и CLI `doctor`, `backup`, `reproject` — с MVP | stdio ([ADR-0008](0008-mcp-architecture.md)) |

   Доменные операции, инварианты 05 §14 и наборы изменений реализованы один раз. `strata-core` не зависит от `tauri`, `axum` и `rmcp` — это проверяет граф крейтов ([15](../15-architecture.md) §2.3). CLI `strata` поставляется с десктопом как sidecar (`bundle.externalBin`).
2. **Одна SPA для десктопа и веба.** Vite собирает один артефакт. Tauri отдаёт его своим протоколом без localhost-сервера, `strata serve` — с того же домена, что API ([R4](../research/R4-app-shell-rendering.md) §1.7, [15](../15-architecture.md) §5.4).
3. **Интерфейс `Backend`** ([15](../15-architecture.md) §2.5, [10](../10-storage-sync-collab.md) §4):
   - `TauriBackend`: `invoke` — для доменных операций (JSON, сотни байт); `tauri::ipc::Response` с ArrayBuffer — для выписок; каналы Tauri — для дельт, присутствия и апдейтов редакторов. Event system Tauri для потоков не используем: она «is not designed for low latency or high throughput» ([R4](../research/R4-app-shell-rendering.md) §1.4).
   - `RemoteBackend`: HTTPS — для выписок и ассетов, WebSocket — для комнат и операций. Тонкий клиент без CRDT индекса (❓ Q-10-1); веб — этап 3, вместе с сервером.
4. **React 19 + React Compiler рисует только Хром:** окна, панели, Tab-меню, палитру, строку пути. Граф и позиции нод живут вне React, холст и карта рисуются императивно; правила горячего пути — [ADR-0005](0005-rendering.md).
5. **Гейт Linux** — спайк 1 на машине владельца MO ([15](../15-architecture.md) §5.3, [14](../14-nfr.md) §1.2):

   | Критерий | Порог |
   |---|---|
   | Холст N-5k в WebKitGTK | NFR-01: p95 ≤ 16,7 мс |
   | Карта 20 000 звёзд | NFR-12: p95 ≤ 16,7 мс |
   | Стабильность | 30 мин без пустого окна, мерцания, падения при ресайзе и потери WebGL-контекста; без `WEBKIT_DISABLE_DMABUF_RENDERER` и `WEBKIT_DISABLE_COMPOSITING_MODE`, которые отключают быстрый путь |
   | Окружение | Под композитором владельца: `Alt`-жесты, щипок трекпада, `strata://`, хранилище ключей |

   Если гейт не пройден — лестница отступления. UI и ядро не меняются ни на одной ступени:

   | Ступень | Что | Когда |
   |---|---|---|
   | 0 | Canvas-рендерер Pixi для 2D и настройка «Рендерер: авто / WebGL / Canvas» | Всегда, на всех ОС (NFR-10) |
   | 1 | Linux-сборка на Tauri 3 + CEF | Tauri 3 к этому моменту хотя бы в beta |
   | 2 | Electron-оболочка только для Linux, ядро — sidecar-процесс | Tauri 3 ещё в alpha |
   | 3 | `strata serve` локально + Chromium в режиме `--app` | Временно, пока не готова ступень 1 или 2 |

6. **Обновления.** `tauri-plugin-updater` 2.13.3: подпись обязательна и не отключается; на Linux — AppImage ([R4](../research/R4-app-shell-rendering.md) §1.5). Приватный ключ — в секретах CI и в офлайн-копии у двух человек ([15](../15-architecture.md) §8.6).
7. **Версии.** Tauri закрепляется с точностью до минорной версии; обновление — задача с прогоном бенчмарков ([15](../15-architecture.md) §8.5).

## Альтернативы

1. **Electron + Node-ядро** — запасной стек на случай, если в команде нет Rust (B2, [15](../15-architecture.md) §6).
   - Плюс: один язык. Chromium на всех ОС — Linux-риск исчезает. Ядро — в `utilityProcess` с MessagePort к рендереру ([R4](../research/R4-app-shell-rendering.md) §1.4).
   - Минус: рантайм 117–151 МБ. В тесте Better Stack — 323 МБ против 57 МБ у Tauri и около 128 против 109 МБ памяти после старта (по данным поиска, [R4](../research/R4-app-shell-rendering.md) §1.2). На Linux нужен `electron-updater`; мобильных нет.
   - Минус: ядро, сервер и MCP переходят на TypeScript — `better-sqlite3`, `loro-crdt` в Node, TS SDK MCP. Полнотекст на русском без tantivy не проверен ([15](../15-architecture.md) §6).
   - Выбирается по ответу на B2 до начала работ над ядром: позже смена означает переписать ядро. SPA, `Backend`, формат данных и протокол при этом не меняются.
2. **Wails** ([R4](../research/R4-app-shell-rendering.md) §1.8).
   - Минус: те же системные WebView, что у Tauri, а значит, та же проблема Linux. Ядро на Go — общего с сервером Rust-кода нет. v3 всё ещё beta (`@wailsio/runtime` 3.0.0-beta.29).
   - Neutralinojs слишком тонкий для ядра с БД, индексом и MCP. Deno Desktop интересен как вариант только на TypeScript с выбором Chromium, но пока experimental.
3. **Только веб или PWA**, без десктопа.
   - Плюс: своей оболочки нет вообще; та же SPA ([R4](../research/R4-app-shell-rendering.md) §1.6).
   - Минус: нет локального ядра — соло-режим требует сервера, что противоречит [03](../03-vision.md). Индекс без лимита нод, полнотекст на русском, вотчер и MCP — задачи нативного ядра, а не UI ([R4](../research/R4-app-shell-rendering.md) §7).
   - Минус: нет прямого доступа к папке vault: `showDirectoryPicker` есть только в Chromium, запасной путь — `<input webkitdirectory>` ([R4](../research/R4-app-shell-rendering.md) §1.7). Локальные MCP-клиенты запускают stdio-команду, а не открывают вкладку.
   - Итог: это веб-клиент этапа 3 и кандидат на мобильную версию (❓ Q-15-10), но не замена десктопу.
4. **Tauri 3 + CEF сразу на всех ОС.**
   - Плюс: Chromium везде без смены стека: UI и ядро те же.
   - Минус: alpha (3.0.0-alpha.x), сроки стабилизации не объявлены, есть ломающие изменения (GTK стал opt-in, MSRV — Rust 1.95). Размер CEF-сборки не проверен; у Deno-CEF около 150 МБ (по данным поиска) ([R4](../research/R4-app-shell-rendering.md) §1.1, риск 2).
   - Итог: ступень 1 лестницы — только для Linux и только при провале гейта (❓ Q-15-3).
5. **Svelte 5 или SolidJS вместо React** ([R4](../research/R4-app-shell-rendering.md) §5).
   - Плюс: меньше рантайм, точечные обновления.
   - Минус: Excalidraw пришлось бы встраивать React-островом — два фреймворка в бандле. Solid 2.0 пока RC (2.0.0-rc.14).
   - Скорость фреймворка не решает: горячий путь всё равно живёт вне него. Решает интеграция с Excalidraw.

## Последствия

- ➕ Модель данных, инварианты и правила «Скрыть от AI» реализованы один раз — для десктопа, сервера и MCP ([ADR-0008](0008-mcp-architecture.md)).
- ➕ Веб и десктоп — одна сборка SPA; различается только реализация `Backend`.
- ➕ Малый дистрибутив: минимальное приложение Tauri — меньше 600 КБ ([R4](../research/R4-app-shell-rendering.md) §1.2), цель NFR-54 для плана А достижима; на ступенях 1–2 лестницы и в запасном стеке бюджет пересматривается (❓ Q-15-2, Q-15-3). Подписанный апдейтер встроен. Путь к мобильным через Tauri 2 mobile остаётся открытым.
- ➖ WebKitGTK — риск №1: холст и карта могут «молча» работать медленно, а изнутри это не определить. Снижаем: гейт и лестница; Canvas-фолбэк; пресет качества выбирается по времени кадра, а не по строке рендерера ([08](../08-view-3d.md) §8.4).
- ➖ Три движка WebView плюс Firefox для веба — дорогая матрица тестов (NFR-127, [R4](../research/R4-app-shell-rendering.md), риск 4). Снижаем: свои GPU-раннеры под Linux, Windows и macOS (❓ Q-15-12).
- ➖ WKWebView обновляется только с ОС и может держать потолок 60 Гц. Цель — 60 fps, а не 120 (NFR-119, ❓ Q-14-2). Минимум — macOS 13, как у Electron 44, чтобы запасной путь не сузил поддержку ([14](../14-nfr.md) §15).
- ➖ Нужна компетенция в Rust. Без неё — запасной стек (альтернатива 1); ответ на Q-15-2 нужен до работ над ядром.
- ➖ Граница UI ↔ ядро дорога для больших данных. Снижаем: выписки — ArrayBuffer, потоки — каналы, никаких JSON-массивов на 100 000 объектов ([15](../15-architecture.md) §4.4). `SharedArrayBuffer` не используем: COOP и COEP в протоколе Tauri не проверены ([R4](../research/R4-app-shell-rendering.md) §3.5).
- ➖ Не проверено, вынесено в спайк 1: как Tauri держит процесс без окон для агентов (❓ Q-12-9); один экземпляр и глубокие ссылки `strata://`; OffscreenCanvas 2D в WebKitGTK; отдача ассетов в WebView.
- ➖ Потеря ключа апдейтера означает, что выпускать обновления больше нельзя. Подпись кода ОС не исследована (❓ Q-15-11).

**Условия пересмотра.** Ответ на B2 «только TypeScript» — новый ADR о переходе на Electron + Node-ядро, этот помечается «Заменён». Провал гейта — отдельный ADR о Linux-сборке (ступени 1–3); этот остаётся в силе для Windows и macOS. Стабильный Tauri 3 с CEF приемлемого размера — повод пересмотреть рантайм для Linux.
