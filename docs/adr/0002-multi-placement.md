# ADR-0002. Одна нода — много размещений, вложенность без циклов

- Статус: Принято (2026-10-19, по делегированию владельца)
- Дата: 2026-10-13
- Связано: [05-domain-model.md §5](../05-domain-model.md#5-размещение-placement), [ADR-0001](0001-global-edges.md), [10-storage-sync-collab.md §2.3](../10-storage-sync-collab.md#23-шард-индекса), [13-interop.md §2.7.1](../13-interop.md#271-элементы)
- Уточнено: [ADR-0010](0010-kinds-not-classes.md) — холст и размещения есть у папки и проекта; задача холста не имеет

## Контекст

- ✅ C3: иерархия максимально гибкая; одна нода (например, референсы) может использоваться в нескольких проектах «столько раз, сколько нужно».
- ✅ G3 (бриф): нужен путь до ноды «как в файловом менеджере».
- ✅ C2: у ноды одно содержимое, а сеть — один из видов ноды.
- ✅ Q-05-1 (раунд 2): задача — сеть с «Описанием» и «Требованиями», сроками, ответственными и подзадачами; подзадача — нода класса «Задача» внутри сети задачи ([05 §4.3](../05-domain-model.md#43-классы-nodeclass-и-задача)). Связь «задача — подзадача» — это вложенность сетей, то есть размещение.

Файловое дерево даёт простые пути, но не даёт одной ноде жить в нескольких местах. Граф без иерархии даёт гибкость, но теряет пути и «погружение».

## Решение

Разделяем **ноду** (сущность с содержимым) и **размещение** (факт «нода лежит в сети N»).

- У ноды одно **основное** размещение и сколько угодно **появлений**.
- В одной сети нода размещена не больше одного раза.
- Вложенность сетей ацикличная: нельзя поместить сеть в саму себя или в своего потомка.
- Канонический путь строится по основным размещениям. Ссылки всегда содержат ID ноды, путь в них — подпись.
- `Ctrl+V` создаёт независимую копию, «Вставить как появление» (`Ctrl+Shift+V`) — новое размещение той же ноды.
- «Убрать отсюда» удаляет размещение, «Удалить везде» отправляет ноду в корзину.
- «Сделать основным» переназначает основное размещение: ID и ссылки не меняются, меняется канонический путь.

### Хранение

- У размещения нет собственного ID. Его ключ — `{networkId}/{nodeId}`: два клиента, одновременно положившие ноду в одну сеть, пишут один ключ, и правило «не больше одного раза в сети» держится без сверки ([05 §5](../05-domain-model.md#5-размещение-placement), §14 п. 1).
- Признак основного размещения — поле ноды `primaryNetworkId`, а не флаг `isPrimary` на каждом размещении. Одно значение на ноду всегда даёт ровно одно основное; булев флаг при параллельных «Убрать отсюда» дал бы ноль или два ([10 §2.3](../10-storage-sync-collab.md#23-шард-индекса)). Если `primaryNetworkId` указывает на размещение, которое параллельно убрали, основным становится самое старое из оставшихся ([10 §8.5](../10-storage-sync-collab.md#85-межшардовые-операции-и-сверка-инвариантов)).
- Документ сети адресует раскладку и членство в рамках по `nodeId`: внутри сети N нода однозначно задаёт размещение `N/nodeId`.

## Альтернативы

1. **Строгое дерево + ярлыки-ссылки** (как ярлыки в Windows): ярлык — отдельная нода, указывающая на оригинал. Отклонено: у ярлыка свои нити и свои атрибуты, путаница «правлю ярлык или оригинал».
2. **Чистый граф без вложенности** (как Obsidian graph или TheBrain): отклонено — нет погружения в задачу, нет путей, нет ленивой загрузки по сетям.
3. **Транклюзия только содержимого** (как embed в Obsidian): закрывает тексты, но не закрывает ноду целиком с её нитями и атрибутами.

## Последствия

- ➕ Нода референсов в трёх проектах — одна: обновил в одном месте, изменилось везде.
- ➕ Есть и пути, и гибкость: человек видит знакомую иерархию, а связи не ограничены деревом.
- ➖ У ноды может быть много путей; при вложенных появлениях их число растёт быстро. Снижаем: показываем канонический путь, остальные вычисляем лениво.
- ➖ Удаление нужно объяснять: «убрать отсюда» и «удалить везде» — разные действия с разными иконками и подтверждением. ☑ Q-05-6: при удалении сети вложенные ноды без других размещений уходят в корзину вместе с ней, остальные теряют только это размещение; перед удалением — диалог с числом затронутых нод и перечнем их путей ([05 §5](../05-domain-model.md#5-размещение-placement)).
- ➖ Свёртки (прогресс, дедлайны) должны считать ноду один раз, даже если она размещена в нескольких местах внутри сети. ☑ Q-05-2: свёртки — по всей глубине вложенности, каждая нода один раз, ноды на паузе не участвуют; прогресс и ближайший срок задачи — свёртка по подзадачам (✅ Q-05-1, [05 §6.4](../05-domain-model.md#64-свёртки-roll-up)).
- ➖ При импорте из Obsidian дерево папок даёт только основные размещения; file-карточки `.canvas` на файлы из других папок дают появления ([13 §2.7.1](../13-interop.md#271-элементы)). Экспорт появлений — file-карточки в `.canvas` других сетей ([13 §4.1](../13-interop.md#41-где-что-лежит)).
