# ADR-0008. Архитектура MCP-сервера

- Статус: Предложено
- Дата: 2026-10-13
- Связано: [12-mcp-ai.md](../12-mcp-ai.md), [05-domain-model.md](../05-domain-model.md) (§7 флаги, §11 наборы изменений), [04-personas-scenarios.md](../04-personas-scenarios.md) (P4, S8), [10-storage-sync-collab.md](../10-storage-sync-collab.md) (§3.1 лок, §9 наборы изменений), [11-server-selfhost.md](../11-server-selfhost.md), [15-architecture.md](../15-architecture.md) (§5.2 процессы), [16-roadmap.md](../16-roadmap.md) (§4.5, §5.2 этапы), [ADR-0003](0003-sync-engine.md), [ADR-0004](0004-app-shell.md); исследования [R6](../research/R6-mcp-ai.md) (главное), [R3](../research/R3-crdt-sync.md), [R4](../research/R4-app-shell-rendering.md), [R5](../research/R5-board-engine.md)

## Контекст

Требования:
- ✅ K1: дать доступ к графу для Claude и Codex; AI ищет по содержимому, структурирует тексты и картинки, кладёт картинки на холсты.
- ✅ J2: совместная работа в реальном времени обязательна — агенту нужен доступ и к командному self-hosted серверу.
- ✅ B1: приоритет — веб и десктоп. Следствие: веб-пользователь подключает агента к серверу, а не к локальному приложению.
- ✅ G1: поиск по содержимому в интерфейсе не нужен, его делает AI через MCP.
- ✅ N1: содержимое грузится лениво — MCP не должен открывать всё пространство ради поиска.
- K2 (права агента) и K3 (локально или удалённо) без ответа; предложения — в [12](../12-mcp-ai.md), вопросы Q-12-1, Q-12-2, Q-12-6.
- Этап: MCP нет в ✅ O1, поэтому локальный MCP — релиз MVP+ 1.1; в MVP — его основания: доменные операции в ядре, наборы изменений с источником, IPC-сокет, проекция ([16](../16-roadmap.md) §4.5, ❓ Q-16-2).

Факты, которые ограничивают выбор ([R6](../research/R6-mcp-ai.md)):
- Спецификация MCP сменилась: текущая ревизия `2026-07-28` stateless, без `initialize` и сессий; сервер, знающий только её, ломает клиентов `2025-11-25`. Клиенты в переходном состоянии: Claude Code умеет новую ревизию, Codex и Claude Desktop — не проверено (§1.1, §2).
- Claude Desktop в конфиге принимает только локальные stdio-серверы; его custom connectors ходят из облака Anthropic и не видят `localhost` и LAN (§2.2).
- Codex в режиме `writes` решает, спрашивать ли подтверждение, по `readOnlyHint`; инструмент без аннотаций клиенты считают разрушающим (§1.3, §2.3).
- Claude Code: ответ инструмента — до 25 000 токенов по умолчанию, предупреждение с 10 000 (§2.1).
- Base64 в аргументах инструментов портит файлы (§3).
- `rmcp` 3.5.1 (Apache-2.0) поддерживает обе ревизии, stdio и Streamable HTTP; серверного OAuth в нём нет; три мажорные версии за полгода (§1.6).

Уже решено предложениями других документов: одно Rust-ядро для десктопа, сервера и CLI ([R4](../research/R4-app-shell-rendering.md)); источник правды — CRDT Loro, чтение для поиска — SQLite-проекция ([R3](../research/R3-crdt-sync.md)); набор изменений с источником `mcp:<клиент>` (05 §11, структура — [10](../10-storage-sync-collab.md) §9.1); процессная модель десктопа — ядро в процессе окна или `strata core --headless` ([ADR-0004](0004-app-shell.md) п. 1, [15](../15-architecture.md) §5.2).

## Решение

**MCP-сервер живёт в Rust-ядре Strata и вызывает те же доменные операции, что интерфейс. Входов два: `strata mcp` (stdio-лаунчер к работающему ядру) и `/mcp` (Streamable HTTP) на self-hosted сервере. Сервер поддерживает ревизии `2025-11-25` и `2026-07-28` одновременно.**

Детали:

1. **SDK.** `rmcp` 3.x с точно закреплённой версией за тонким адаптером. MCP-слой — разбор аргументов, политика и формат ответа; бизнес-логики в нём нет.
2. **Локальный вход `strata mcp`.** Тот же бинарник `strata`. Подключается к ядру по Unix-сокету или именованному каналу (права пользователя ОС, токен сокета). Ядро живёт в процессе окна; если окна нет — лаунчер поднимает `strata core --headless`, которое выходит через 10 мин после ухода последнего клиента (Q-12-9); при открытии окна headless-ядро сбрасывает данные и передаёт лок `.lock` окну ([15](../15-architecture.md) §5.2, [10](../10-storage-sync-collab.md) §3.1). У пространства один писатель, правка агента сразу видна на холсте.
3. **Мост `strata mcp --remote <url>`.** Прозрачный транспорт stdio ↔ Streamable HTTP с токеном из окружения. Даёт Claude Desktop доступ к серверу в LAN без Node.js и `mcp-remote`.
4. **Серверный вход `/mcp`.** Этап 3а — персональные токены с областями `strata:read` / `write` / `delete`, привязкой к пространству и поддеревьям. Этап 3б — OAuth 2.1 (PRM RFC 9728, PKCE S256, CIMD, проверка аудитории) для custom connectors; встроенный AS или внешний OIDC — решение в [11](../11-server-selfhost.md).
5. **Локальный HTTP** `127.0.0.1` в ядре десктопа — опция этапа 2, выключена по умолчанию, с проверкой `Origin` и токеном.
6. **Инструменты.** 26 в релизе MVP+ 1.1, 28 в полном наборе ([12](../12-mcp-ai.md) §4.2). У каждого явно все четыре аннотации. Набор в `tools/list` зависит от прав подключения. Входные схемы плоские; ответы короткие, с путём и ID в каждой строке, ≤ 20 000 токенов.
7. **Политика в ядре, а не в клиенте.** Флаг «Скрыть от AI» (05 §7) и область поддерева проверяются в слое политики над проекцией; скрытое отвечает `NOT_FOUND`. «Замок» соблюдается; флаги «Замок» и «Скрыть от AI» агент не меняет.
8. **Журнал и откат с первого релиза MCP.** Каждый вызов записи — один набор изменений ([10](../10-storage-sync-collab.md) §9.1): источник `mcp:<клиент>`, отдельный `peerId` Loro, подпись, значения ключей до и после. Наборы изменений с откатом есть уже в MVP; поверх них — журнал агентов `AgentLog`. Откат одной кнопкой в панели «Действия агентов» и инструментом `revert_changeset` — по [10](../10-storage-sync-collab.md) §9.3, в пределах прав владельца токена (10 §9.4); удаление только мягкое.
9. **Подтверждения.** Массовые (> 20 нод) и удаляющие операции — через `dry_run` и `confirm_token` или elicitation, где клиент её поддерживает; параллельно — тост в окне Strata.
10. **Файлы — мимо контекста модели.** Локальный путь из разрешённых каталогов (MVP+ 1.1), тикет загрузки с одноразовым URL (этап 2); base64 не принимаем.

## Альтернативы

1. **Отдельный Node-сервер на TypeScript SDK** (`@modelcontextprotocol/server` 2.3.1, [R6](../research/R6-mcp-ai.md) §1.6).
   - Плюс: Tier 1 SDK, есть серверные auth-хелперы, реализует `2026-07-28`.
   - Минус: вторая реализация модели данных, доменных операций, проекции и правил «Скрыть от AI» рядом с Rust-ядром ([R4](../research/R4-app-shell-rendering.md): одно ядро). Расхождения в инвариантах 05 §14 неизбежны.
   - Минус: Node.js в поставке десктопа или отдельный процесс-посредник.
   - Остаётся запасным путём только вместе с вариантом «Electron + Node-ядро» ([R4](../research/R4-app-shell-rendering.md)), если в команде нет Rust (B2): тогда весь стек на TypeScript, и MCP переходит на TS SDK v2.
2. **Только удалённый MCP на сервере.**
   - Плюс: одна точка входа, единая авторизация, журнал на сервере.
   - Минус: соло-режим без сервера остаётся без агентов, а ✅ K1 нужен и соло-пользователю ([03](../03-vision.md): «Соло-режим не требует сервера и аккаунта»).
   - Минус: Claude Desktop к серверу в LAN без моста не подключится, а custom connectors требуют публичного HTTPS ([R6](../research/R6-mcp-ai.md) §2.2).
3. **Только локальный MCP.**
   - Плюс: проще, нет OAuth и серверной поверхности атаки.
   - Минус: веб-пользователь и команда (✅ J2, ✅ B1) остаются без агентов; агенту на чужой машине некуда подключиться.
4. **MCP как плагин Obsidian** (агент работает с `.md`-файлами vault, Strata их подхватывает).
   - Плюс: агент работал бы с привычными `.md`-файлами. Существующие MCP-плагины Obsidian в исследованиях не рассматривались — не проверено.
   - Минус: Obsidian — проекция, а не источник правды Strata ([R2](../research/R2-obsidian-format.md), [13](../13-interop.md)): размещения, нити `strata-inputs`, доски и атрибуты агент видел бы в урезанном виде, графовых операций (`insert_into_edge`, `place_node`, `apply_graph_plan`) нет.
   - Минус: нет наборов изменений, отката, «Скрыть от AI» и подтверждений; агент зависит от запущенного Obsidian.
5. **stdio-процесс, который открывает пространство сам** (вариант A в [R6](../research/R6-mcp-ai.md), «Сравнение»).
   - Плюс: не нужен IPC.
   - Минус: два писателя при открытом окне, конфликт локов SQLite и CRDT, правки агента не видны на холсте до перечитывания. Используем только как часть варианта 2 решения: лаунчер поднимает то же ядро без окна.
6. **Основной вход — HTTP внутри приложения на `127.0.0.1`** (вариант C в [R6](../research/R6-mcp-ai.md)).
   - Плюс: без лаунчера, клиенты Claude Code, Codex и Cursor подключаются по URL.
   - Минус: Claude Desktop не принимает `url` в конфиге; работает, только пока окно открыто; риск DNS rebinding. Оставлен опцией, выключенной по умолчанию.

## Последствия

- ➕ Одна модель данных и одни инварианты для UI, импорта и агентов; правка агента сразу видна на холсте и у соавторов.
- ➕ Покрыты все целевые клиенты: Claude Code, Codex, Cursor напрямую; Claude Desktop — через stdio, `.mcpb` и мост `--remote`.
- ➕ Доверие к агенту строится на журнале и откате, а не на подтверждении каждого шага.
- ➕ «Скрыть от AI» и области токенов проверяются в одном месте, общем для локального и серверного входа.
- ➖ Темп `rmcp` (три мажорные версии за полгода). Снижаем: точная версия, адаптер, контрактные тесты на каждый инструмент.
- ➖ Две ревизии протокола — больше тестов. Снижаем: спайк по клиентам ([12](../12-mcp-ai.md) §11.2 п. 1), матрица «клиент × ревизия» в CI; отказ от `2025-11-25` — не раньше, чем все целевые клиенты перейдут на новую ревизию (для ориентира: устаревшие возможности спецификация держит минимум 12 месяцев, [R6](../research/R6-mcp-ai.md) §1.1).
- ➖ IPC-лаунчер и ядро без окна — новый процесс и новые сбои: ядро не стартовало, версии лаунчера и ядра разошлись. Снижаем: `strata mcp --check`, проверка версии при рукопожатии, понятные ошибки в stderr.
- ➖ Серверного OAuth в `rmcp` нет — его пишем сами или берём внешний OIDC. Снижаем: этап 3а на персональных токенах, OAuth — отдельным шагом 3б.
- ➖ Rust-ядро пишет элементы Excalidraw без DOM и не рисует миниатюры досок ([R5](../research/R5-board-engine.md), риск 7). Снижаем: адаптер `BoardEngine`, тесты схемы, флаг `thumbnail_stale`.
- ➖ Область поддерева проверяется над проекцией, а не на уровне синхронизации: агент её соблюдает, но клиент-человек с правами на пространство видит всё ([R3](../research/R3-crdt-sync.md), риск 9). Для MCP этого достаточно; права людей на поддеревья — вопрос [11](../11-server-selfhost.md).
- Пересмотреть решение, если: спайк покажет, что `rmcp` не договаривается с одним из целевых клиентов; команда выберет «Electron + Node-ядро»; спецификация MCP получит стандарт загрузки файлов (тогда тикеты заменяются им).
