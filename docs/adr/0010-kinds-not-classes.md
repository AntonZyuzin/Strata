# ADR-0010. Виды вместо классов

- Статус: Принято (2026-10-24, владелец)
- Дата: 2026-10-24
- Связано: [05](../05-domain-model.md) §4.2–4.3, §6.4, §8; [07](../07-design-system.md) §4.4, §6.1; [glossary](../glossary.md); заменяет ✅ Q-05-1 (R2) в части «задача — класс поверх сети»

## Контекст

С R2 у ноды две оси: вид (что внутри: сеть, заметка, доска, список, медиа) и класс (заготовка поверх вида: «Задача», «Проект», «Референсы», «Чек-лист»). На сборке вехи 1B владелец увидел путаницу:

- «Задача» и «Проект» — одна и та же сеть с разной подписью; «Референсы» ничем не отличаются от доски, «Чек-лист» — от списка.
- В задачу проваливаются, хотя задача — единица работы со сроком и ответственными, а не раздел.
- Поля задачи (статус, сроки, люди) показывались у любой ноды, в том числе у заметки.

Ответ владельца 2026-10-24: «Задача — единица с дедлайном, ответственными и т. д., в которую нельзя провалиться»; «Проект — задача, в которую можно провалиться»; подзадачи — задачи, присоединённые к задаче нитью: на холсте они отдельные ноды, а в свойствах задачи — превью-чеклист иерархии; ассет — фото, видео, звук, ссылка или файл со значком по содержимому, который можно сменить руками.

## Решение

Классов нет. Семь видов, у каждого свой набор свойств:

| Вид | Код | Внутрь | Свойства |
|---|---|---|---|
| Папка | `network` | Да | Имя, цвет, описание |
| Проект | `project` | Да | Поля задачи, описание; прогресс и ближайший срок по задачам внутри |
| Задача | `task` | Нет | Статус, приоритет, начало, дедлайн, ответственные, описание; подзадачи — по нитям |
| Заметка | `note` | Редактор | Имя, цвет, текст |
| Доска | `board` | Доска | Имя, цвет, сцена |
| Список | `checklist` | Нет: пункты — в панели | Имя, цвет, пункты с галочками |
| Ассет | `asset` | Просмотр | Файл (картинка, видео, звук, прочее) или ссылка, тип, значок, описание |

- Поля задачи (`status`, `priority`, `start`, `deadline`, `assignees`) есть только у задачи и проекта; ядро отвергает их на других видах.
- Описание задачи, проекта, папки и ассета — их собственный документ содержимого `content/<id>` (10 §2.4), а не отдельная заметка внутри.
- Нить от задачи или проекта к задаче делает приёмник **подзадачей** (05 §8.1: источник — «родитель»). Типов нитей по-прежнему нет (✅ C4): смысл даёт пара видов на концах. Нить от задачи к заметке, ассету, доске или списку — **материал** задачи.
- Прогресс задачи — по подзадачам по нитям на всю глубину, каждая один раз; прогресс проекта и папки — по задачам внутри на всю глубину и их подзадачам по нитям.
- Ассет: `asset` — SHA-256 файла (10 §11), `mime`, `url` — ссылка вместо файла, `icon` — значок, выбранный руками. Значок по умолчанию — по типу содержимого.
- В коде вид папки остаётся `network`, а слово «сеть» — техническим: так называется холст внутри папки или проекта.

## Альтернативы

- **Оставить классы и поправить подписи** — не снимает главного: задача остаётся сетью, в которую проваливаются.
- **Подзадачи — пункты с галочками внутри задачи.** Проще, но у пункта нет своих сроков и людей; владелец выбрал полноценные задачи по нитям.
- **Тип нити «подзадача» и «блокирует».** Противоречит ✅ C4; если блокировки понадобятся, их даст подпись нити.
- **Убрать папку, оставить только проект.** Тогда у разделов с заметками появляются пустые статусы и сроки — лишние элементы.

## Последствия

- Модель (05 §4.1–4.3, §6.4, §8), глоссарий, 07 §4.4 и §6.1, дорожная карта 1B меняются под это решение.
- Пространства, созданные до решения, не переносятся (владелец: «можешь удалить их»): ядро читает их без классов, задачи-сети открываются как папки, вид `media` читается как `asset`.
- Окно списка и палитра цветов доски — следующие шаги 1B.
- Дополнение 2026-10-24 (владелец): у списка нет своего окна — пункты с галочками и вложенностью правятся в панели свойств, как поля задачи; прогресс «N из M» — в заголовке «Пункты» и дугой на кромке бабла.
