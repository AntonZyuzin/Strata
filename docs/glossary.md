# Глоссарий

Единые термины для документации, интерфейса и кода. В интерфейсе используем русский термин, в коде — английский.

| Термин | В коде | Определение |
|---|---|---|
| Пространство | `Workspace` | Всё, что принадлежит одной базе: ноды, нити, ассеты, настройки. Аналог vault в Obsidian. Бывает локальным или на сервере |
| Нода | `Node` | Единица содержимого: бабл на холсте. Существует в одном экземпляре, но может быть размещена в нескольких сетях |
| Вид ноды | `NodeKind` | Тип содержимого ноды: сеть, заметка, доска, список, медиа. Выбирается при создании и не меняется |
| Класс | `NodeClass` | Именованная заготовка поверх вида: вид + набор атрибутов + иконка по умолчанию. Например, «Задача» — это сеть с атрибутами задачи |
| Подзадача | `subtask` | Нода класса «Задача», размещённая внутри сети другой задачи. Отдельной сущности нет — это вложенность сетей; прогресс и ближайший срок задачи — свёртка по подзадачам ([05](05-domain-model.md) §4.3, ✅ Q-05-1) |
| Сеть | `Network` | Нода, содержимое которой — холст с другими нодами. Аналог subnet в Houdini или папки в файловом менеджере |
| Корневая сеть | `RootNetwork` | Верхний уровень пространства, путь `/` |
| Холст | `Canvas` | Видимая область сети в 2D, где лежат баблы, нити, рамки и стикеры |
| Размещение | `Placement` | Факт того, что нода лежит в конкретной сети. Ключ `{networkId}/{nodeId}`, собственного ID нет; позиция — в документе сети. У ноды может быть много размещений, но не больше одного в одной сети ([05](05-domain-model.md) §5) |
| Основное размещение | `primary placement` | Домашнее размещение ноды, по нему строится канонический путь. Задаётся полем ноды `primaryNetworkId`, поэтому всегда ровно одно. Изначально — первое размещение; переназначается командой «Сделать основным» или, если основное убрали, переходит к самому старому из оставшихся ([05](05-domain-model.md) §5) |
| Появление | `instance` | Любое неосновное размещение. Показывается со значком ярлыка, как в Windows |
| Нить | `Edge` | Направленная смысловая связь между двумя нодами. Глобальна: видна в любой сети, где размещены оба её конца (☑ Q-05-5, [ADR-0001](adr/0001-global-edges.md)) |
| Вход / выход | `in-edges` / `out-edges` | Входящие и исходящие нити ноды. Количество не ограничено |
| Выше / ниже по течению | `upstream` / `downstream` | Все ноды, от которых нода зависит по нитям, и все, что зависят от неё |
| Точка | `Dot` | Точка-перегиб на нити, принадлежит сети. Через неё можно разветвлять нить |
| Рамка | `NetworkBox` | Цветная сворачиваемая рамка, группирующая ноды на холсте. Аналог network box в Houdini |
| Стикер | `StickyNote` | Короткая надпись на холсте, не являющаяся нодой. Аналог sticky note в Houdini |
| Флаг | `Flag` | Переключаемое состояние ноды: ключевая, пауза, шаблон, скрыть от AI, замок. Аналог флагов Houdini |
| Призрак | `Ghost` | Неразрешённая ссылка `[[X]]` на несуществующую ноду. Рисуется пунктирным баблом; клик создаёт ноду |
| Проекция | `Projection` | Производная копия данных в SQLite для поиска, путей, свёрток, 3D и MCP. Пересобирается из CRDT |
| Шард индекса | `Index shard` | Часть индекса пространства; ноды распределены по шардам по хешу ID |
| Атрибут | `Attribute` | Именованное типизированное значение ноды: статус, дедлайн, ответственные, теги, алиасы, пользовательские поля ([05](05-domain-model.md) §6) |
| Статус | `status` | Встроенный атрибут состояния (например, «В работе», «Готово») |
| Свёртка | `roll-up` | Значение сети, вычисленное по вложенным нодам: прогресс, ближайший дедлайн, наличие просрочки. Считается по всей глубине, каждая нода — один раз, ноды на паузе не участвуют ([05](05-domain-model.md) §6.4, ☑ Q-05-2) |
| Путь захода | `arrival path` | Цепочка сетей, по которой пользователь пришёл в текущую сеть. Показывается в строке пути, по нему работает `U`; канонический путь — серым ниже ([05](05-domain-model.md) §9.3). Синоним «маршрут захода» не используем |
| Путь | `Path` | Человекочитаемая цепочка имён сетей до ноды: `/Проекты/Игра/Спринт 3/Задача` |
| Канонический путь | `canonical path` | Путь по основным размещениям |
| Глубокая ссылка | `Deep link` | Ссылка на ноду по стабильному ID, которая переживает переименование и перенос. Форматы — [05](05-domain-model.md) §9.4 |
| Tab-меню | `Tab menu` | Всплывающий поиск под курсором для создания нод и вставки существующих |
| Индекс пространства | `Workspace index` | Метаданные всех нод, размещения и нити: K шардов индекса и документ производных ([10](10-storage-sync-collab.md) §2). На десктопе и сервере загружен всегда; тонкий веб видит его через выписки |
| Документ сети | `Network doc` | Раскладка конкретной сети: позиции, точки, рамки, стикеры. Грузится при входе в сеть |
| Документ содержимого | `Content doc` | Тело ноды: текст, сцена доски, пункты списка. Грузится при открытии ноды |
| Ассет | `Asset` | Бинарный файл: картинка, PDF, иконка, фон. Хранится по хешу содержимого |
| Превью | `Preview` | Краткая справка ноды в индексе: сниппет текста, миниатюра, счётчики. Используется для подсказок и 3D без загрузки содержимого |
| Набор изменений | `Changeset` | Группа изменений одной операции пользователя, агента, импорта или ведущего ядра — с автором, временем и источником (`user`, `mcp:<клиент>`, `ai`, `import`, `system`). Хранит значения затронутых ключей до и после; откатывается целиком ([05](05-domain-model.md) §11, [10](10-storage-sync-collab.md) §9.1) |
| Корзина | `Trash` | Удалённые ноды с возможностью восстановления вместе с размещениями и нитями. Пока нода в корзине, её размещения и нити скрыты, а не удалены ([05](05-domain-model.md) §11) |
| Звёздная карта | `3D view` | 3D-представление всего пространства: ноды — звёзды, сети — скопления |
| Скопление | `Cluster` | Группа звёзд в 3D, образованная вложенностью или связями |
| Отражение | `reflection` | Появление ноды в 3D: звезда одна и стоит в скоплении основного размещения, в скоплениях появлений рисуется её отражение — полое кольцо ([08](08-view-3d.md) §2.3) |
| Контекстная сеть | `context network` | Сеть, от которой в 3D считаются `Tab`, `Delete` и «Где размещена» для выделенной ноды; у отражения — сеть этого отражения ([08](08-view-3d.md) §2.3) |
| Скопление в фокусе | `focused cluster` | Сеть, относительно которой в 3D работают `Tab`, `Ctrl+F` и строка пути. Меняется по `I`, `U`, перелёту к звезде и `Ctrl+O` ([08](08-view-3d.md) §5.1) |
| Туманность | `nebula` | Скопление издалека: на дальнем LOD рисуется одним облаком вместо звёзд ([08](08-view-3d.md) §4.2) |
| Локальный режим (3D) | `local mode` | Показ только окрестности выделенной звезды на N нитей в обе стороны; позиции остаются глобальными. Этап 2 ([08](08-view-3d.md) §6.6) |
| Сирота | `orphan` | Нода без нитей с единственным размещением. Находится запросом `is:orphan`, подсвечивается линзой «Здоровье» ([08](08-view-3d.md) §2.5, [09](09-search-navigation.md) §3.6) |
| 3D-выписка | `StarMapExtract` | Компактная выписка проекции для 3D бинарными массивами, затем дельты по `seq` ([08](08-view-3d.md) §8.3) |
| Линза | `Lens` | Фильтр или подсветка на холсте и в 3D: по статусу, дедлайну, ответственному, тегу |
| Вид-линза | `View` | Альтернативное представление тех же нод: список, канбан, календарь |
| Зеркало Markdown | `Markdown mirror` | Постоянная выгрузка пространства в папку `.md`-файлов, совместимую с Obsidian. Одностороннее: Strata владеет структурой и раскладкой, обратно принимаются только правки текста и свойств заметок ([13](13-interop.md)). Этап 2 |
| Ключ ссылки | `linkKey` | `casefold(NFC(имя))` без `.md`: по нему разрешаются `[[ссылки]]` и строится ключ нити к призраку. Не `norm()` поиска ([13](13-interop.md) §3.4) |
| Реестр импорта | `ImportSource` | Служебные таблицы ядра: источники импорта, их настройки и соответствие файлов нодам. Не синхронизируются ([13](13-interop.md) §3.8) |
| Отчёт импорта | `import report` | Всё, что импорт не перенёс один к одному: призраки, неоднозначные ссылки, неподдерживаемый синтаксис — с действиями по каждой строке ([13](13-interop.md) §3.6) |
| Владелец зеркала | `mirror owner` | Единственный процесс, который пишет в папку зеркала; принятые из Obsidian правки записываются от его имени ([13](13-interop.md) §6.1) |
| Участник | `Member` | Пользователь сервера с доступом к пространству |
| Человек | `Person` | Тот, кого можно назначить ответственным. На сервере — участник, локально — запись в списке людей |
| Роль в пространстве | `workspace role` | Права участника: читатель, редактор, админ или владелец; одна на участника ([11](11-server-selfhost.md) §5) |
| Приглашение | `invite` | Ссылка `https://<сервер>/invite/<токен>` с пространством, ролью и сроком; одно- или многоразовая ([11](11-server-selfhost.md) §6.5) |
| Персональный токен | `PAT` | Токен `strata_pat_…` для MCP и API со скоупами, привязкой к пространству и сроком; права не шире роли хозяина ([11](11-server-selfhost.md) §6.3) |
| Сводная нить | `summary edge` | Отображение нитей между нодами внутри сети S и нодами снаружи: пунктир от бабла S со счётчиком. В данных не хранится |
| Предпросмотр плана | `plan preview` | Показ предлагаемых AI изменений (новые ноды и нити) до применения: точечный обод, альфа 50 %, значок «✦». Не путать с призраком |
| План графа | `GraphPlan` | Плоское описание нод, появлений, нитей и содержимого с временными ID; применяется одной операцией `apply_graph_plan` ([12](12-mcp-ai.md) §13) |
| Тикет загрузки | `upload ticket` | Одноразовый URL для передачи файла в пространство мимо контекста модели ([12](12-mcp-ai.md) §13) |
| Профиль подключения | `connection profile` | Права локального MCP-подключения: «Только чтение», «Чтение и запись», «Полный» ([12](12-mcp-ai.md) §13) |
| Область токена | `token scope` | Права серверного токена: `strata:read` / `write` / `delete`, пространство, поддеревья `within` ([12](12-mcp-ai.md) §13) |
| Порт | `Port` | Зона на кромке бабла, из которой протягивается нить. Входом служит весь бабл |
| Кружок входа | `input socket` | Кружок на кромке приёмника там, где в бабл входит нить: показывает направление без стрелок ([07](07-design-system.md) §5). Только отображение: входом по-прежнему служит весь бабл |
| Инфокарточка | `Info card` | Всплывающая справка о ноде: по удержанию средней кнопки в 2D и при приближении в 3D |
| Кольцо флагов | `Flag ring` | Кольцо вокруг бабла при наведении с переключателями флагов |
| Текущая нода | `current node` | Последняя кликнутая нода; от неё считаются `Tab`, `PgUp`/`PgDn`, `P`. Отмечена «марширующими муравьями». Клавиши флагов действуют на ноду под курсором ([06](06-canvas-ux.md) §8) |
| Строка пути | `Path bar` | Панель над холстом с путём захода, историей и быстрыми метками |
| Быстрая метка | `Quickmark` | Сохранённый вид камеры в сети (`Ctrl+1…5`), аналог quickmarks Houdini. Локальная |
| Избранное | `Favorite` | Ноды, отмеченные для быстрого доступа. Хранится на устройстве; синхронизация между устройствами — по запросу (☑ Q-09-7, [09](09-search-navigation.md) §6.3). Этап — MVP+ 1.4 ([16](16-roadmap.md) §5.2) |
| Палитра команд | `Command palette` | Поиск по командам (`Ctrl+P`) |
| Выписка имён | `names extract` | Выписка проекции для поиска и подписей 3D: ID, имя, алиасы, вид, класс, флаги, сети размещений, корзина; около 60 Б на ноду ([09](09-search-navigation.md) §2.7) |
| Недавние | `recent` | Последние 50 нод на устройстве: сети, в которые входили, открытые ноды, цели `Ctrl+O`, созданные ноды. Локальное состояние ([09](09-search-navigation.md) §6.4) |
| Быстрый захват | `quick capture` | Запись из мини-окна по глобальной клавише или командой `strata capture` во «Входящие». Этап 2, десктоп ([16](16-roadmap.md) §6.2); подробности — [09](09-search-navigation.md) §7 |
| Входящие | `Inbox` | Сеть в корне `/Входящие` для быстрого захвата: каждая запись — отдельная нода ([09](09-search-navigation.md) §7, ☑ Q-09-10) |
| Окно содержимого | `Content window` | Ретро-окно, в котором открыта заметка, доска, список или медиа |
| Режим фокуса | `Focus mode` | Где сейчас ввод: холст, оверлей (Tab-меню, диалог, палитра), поле ввода, окно содержимого, 3D ([06](06-canvas-ux.md) §1.1, [08](08-view-3d.md) §5.2). Однобуквенные клавиши работают только при фокусе на холсте или в 3D |
| Сцена | `Scene` | Визуальный слой холста и 3D: туман, баблы, нити |
| Хром | `Chrome` | Интерфейс вокруг сцены: ретро-окна, панели, меню, диалоги |
| Пиксельная единица | `u` | `u = max(1, round(DPR))`; все пиксельные размеры хрома кратны `u` ([07](07-design-system.md) §2.3) |
| Режим читаемости | `Readable mode` | Тема без пиксельных шрифтов и эффектов для долгой работы и доступности |
| Гало | `Halo` | Мягкое свечение вокруг бабла, кодирующее близость срока |
| Маска иконки | `Icon mask` | Монохромная производная иконки 32/64/128 px, построенная конвейером стилизации |
| Журнал действий агентов | `AgentLog` | Представление журнала наборов изменений с источниками `mcp:*` и `ai`, с откатом одной кнопкой. В интерфейсе — панель «Действия агентов» ([12](12-mcp-ai.md) §6.7) |
| Камера-мост | `camera bridge` | Анимированный переход между 2D-холстом сети и 3D-картой: камера «отъезжает» от сети в её скопление и обратно ([08](08-view-3d.md)) |
| Виджет доски | `board widget` | Короткая заметка или to-do прямо на доске (embeddable в Excalidraw). Не нода ([ADR-0006](adr/0006-board-engine.md)). Ссылка — `strata://<workspace-id>/widget/<board-id>/<widget-id>` ([05](05-domain-model.md) §9.4) |
| Лёгкий режим редактора | `editor light mode` | Тот же редактор заметок без панелей — для виджета «Заметка» на доске ([ADR-0007](adr/0007-text-editor.md) п. 8, [ADR-0006](adr/0006-board-engine.md)) |
| Рабочая копия | `working copy` | Уменьшенная WebP-версия картинки для доски; оригинал хранится в ассетах по SHA-256 |
| Ведущее ядро | `authority core` | Единственный писатель вычисляемых данных, сверки инвариантов, перешардирования и очистки: локальное ядро для локального пространства, сервер — для серверного ([10](10-storage-sync-collab.md)) |
| Манифест | `manifest` | Документ пространства: имя, корневая сеть, настройки, локальные люди. Служебную часть `sys` (версия схемы, K, участники сервера) пишет только ведущее ядро ([10](10-storage-sync-collab.md) §2.2) |
| Документ производных | `derived doc` | Вычисляемая часть индекса пространства: превью, свёртки, ID миниатюр. Пишет только ведущее ядро ([10](10-storage-sync-collab.md) §2.2) |
| Реплика | `replica` | Полная копия серверного пространства на десктопе в папке того же формата; работает офлайн ([10](10-storage-sync-collab.md) §3.7) |
| Комната | `room` | Единица синхронизации и проверки прав: один документ (манифест, шард, сеть, содержимое) внутри общего WebSocket ([10](10-storage-sync-collab.md) §8.1) |
| Лента изменений | `change feed` | Монотонный `seq` принятых апдейтов пространства; по нему клиент после переподключения тянет только изменившееся ([10](10-storage-sync-collab.md) §8.2) |
| Выписка | `extract` | Компактная копия части проекции для клиента (имена, 3D, сеть) с `seq`; дальше приходят дельты ([10](10-storage-sync-collab.md) §7.3) |
| Исходящие | `outbox` | Локальные апдейты, ещё не подтверждённые сервером; уходят по порядку после переподключения ([10](10-storage-sync-collab.md) §8.2). Не путать с исходящими нитями (выходами) |
| Окончательное удаление | `purge` | Удаление ноды навсегда: ключи, документы и история уходят, ID записывается в `purged`. Делает только ведущее ядро ([10](10-storage-sync-collab.md) §10.4) |
| Спасённые правки | `rescued edits` | Свои правки, которые сервер отверг (документ удалён навсегда, шард закрыт): сохраняются в `rescued/` и показываются тостом ([10](10-storage-sync-collab.md) §10.4) |
| Гейт качества | `quality gate` | Проверка с порогами: не пройдена — этап не закрыт или включается запасной путь. Главный — гейт графики: спайк 1 на macOS (WKWebView) и Windows (WebView2) на машинах владельца по сборкам из CI и веб-странице бенчмарка (Safari ≈ WKWebView, Edge и Chrome ≈ WebView2). Linux (WebKitGTK) проходит автотесты в CI и этап не блокирует (✅ R2, Q-15-1; [15](15-architecture.md) §5.3) |
| Лестница отступления | `fallback ladder` | Заранее выбранные запасные ступени при провале гейта графики на одной из платформ: Canvas-фолбэк → Tauri 3 + CEF → Electron-оболочка для этой платформы ([15](15-architecture.md) §5.3) |
| Этапы | `Stage 0 / MVP / MVP+ / 2 / 3 / 4` | Этап 0 — каркас и спайки; MVP — первая версия по ✅ O1, выпускается в два шага: 1.0-α «Переезд» → 1.0 (☑ Q-16-4); MVP+ — релизы 1.1–1.4 сразу после MVP; этап 2 — «Глубина»; этап 3 — «Команда»; этап 4 — «Экосистема». Календарных сроков нет, прогресс — по вехам (✅ R2, B3). Источник истины по этапам — [16](16-roadmap.md) |
| Веха | `milestone` | Шаг внутри этапа, например 1A «Скелет». Заканчивается сборкой из CI, которую владелец проверяет на macOS и Windows по короткому чек-листу (✅ R2, B3; [16](16-roadmap.md) §4.7) |
| Значок состояния | `state badge` | Маленький пиксельный значок на кромке бабла (статус, срок, флаг, появление); дублирует цвет формой ([07](07-design-system.md)) |
| Присутствие | `presence` | Кто из участников сейчас в какой сети и что выделил или правит; идёт по эфемерному каналу ([10](10-storage-sync-collab.md)) |
| Перешардирование | `resharding` | Переход индекса на большее число шардов (1 → 16 → 64) ведущим ядром ([10](10-storage-sync-collab.md)) |
| Администратор сервера | `server admin` | Роль на уровне сервера: пространства, пользователи, резервные копии ([11](11-server-selfhost.md)) |
| Токен устройства | `device token` | Долгоживущий токен, который сервер выдаёт клиенту после входа ([11](11-server-selfhost.md)) |
| Карточка сети | `network card` | Карточка `.canvas` при экспорте, представляющая размещение ноды в сети ([13](13-interop.md)) |
| Форма frontmatter | `frontmatter shape` | Набор и порядок свойств, которые Strata пишет в заметку при экспорте ([13](13-interop.md)) |
| Пункт-задача | `task item` | Строка `- [ ]` в заметке или списке с датами в стиле плагина Tasks; не нода ([13](13-interop.md)) |
