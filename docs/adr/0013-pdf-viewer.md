# ADR-0013. PDF: свой просмотрщик WebView, где он есть, иначе pdf.js

- Статус: Принято (2026-10-31, ☑ Q-06-24 по делегированию владельца)
- Дата: 2026-10-31
- Связано: [06](../06-canvas-ux.md) §13.4, [05](../05-domain-model.md) §4.4, [14](../14-nfr.md), [15](../15-architecture.md) §4, [ADR-0004](0004-app-shell.md), [ADR-0006](0006-board-engine.md), [ADR-0009](0009-license.md)

## Контекст

Ассет-PDF открывается в окне просмотра (06 §13.4) на долю холста, как доска. До этого решения окно показывало файл во фрейме — встроенным просмотрщиком WebView. Он есть в WebView2 (Windows) и WKWebView (macOS), но не в WebKitGTK (Linux) и не в браузерах без просмотрщика: там окно пустое. Владелец делегировал решение (Q-06-24).

Требования: одно окно и один жест на всех ОС; CSP десктопа без `'unsafe-eval'` (`tauri.conf.json`), WASM — через `'wasm-unsafe-eval'`; без CDN; лицензии из списка ADR-0009, GPL-2.0-only не берём; тяжёлое — лениво, как Excalidraw (ADR-0006).

## Решение

**Где WebView показывает PDF сам, окно остаётся фреймом; где нет — страницы рисует pdf.js.** Признак — `navigator.pdfViewerEnabled` (HTML Living Standard): `true` — фрейм с `blob:`, иначе — `PdfView.tsx`.

| Часть | Выбор | Лицензия | Почему |
|---|---|---|---|
| Рендер | [`pdfjs-dist`](https://www.npmjs.com/package/pdfjs-dist) 6.4.299, сборка `legacy` | Apache-2.0 (поле `license` пакета) | Тот же движок, что в Firefox. Современная сборка требует `Promise.withResolvers` (Safari 17.4), а этот путь — как раз для старых WebKit |
| Воркер | `legacy/build/pdf.worker.min.mjs` как файл сборки (`?url`) | Apache-2.0 | Разбор вне главного потока; модульный воркер с того же источника — `script-src 'self'` |
| Карты кодировок | Adobe CMaps из пакета | BSD-3-Clause (`cmaps/LICENSE`) | CJK-документы без встроенных шрифтов |
| Стандартные шрифты | Только Foxit `*.pfb` | BSD-3-Clause (`standard_fonts/LICENSE_FOXIT`) | Liberation Sans из пакета — GPL-2.0 с исключением для шрифтов (`LICENSE_LIBERATION`), то есть GPL-2.0-only: не берём. Без неё Helvetica без встраивания рисуется системным шрифтом без засечек (`useSystemFonts`) |
| Декодеры | `openjpeg.wasm`, `jbig2.wasm`, `qcms_bg.wasm` | BSD-2-Clause, BSD-3-Clause и Apache-2.0, MIT (`wasm/LICENSE_*`) | JPEG 2000 и JBIG2 — частые в сканах; управление цветом CMYK |
| Профиль ICC | `iccs/CGATS001Compat-v2-micro.icc` | CC0 1.0 (`iccs/LICENSE`) | CMYK без своего профиля |

Правила:

1. Код pdf.js грузится с первым таким PDF (`React.lazy` и `import()`), не раньше.
2. Файлы рядом с кодом кладёт в сборку плагин `pdfAssets` в `packages/ui/vite.config.ts` — в `pdfjs/` с текстом каждой лицензии; дев-сервер отдаёт их оттуда же. QuickJS для скриптов PDF не кладём: окно их не выполняет.
3. Страницы — одна под другой во всю ширину окна; страница рисуется, когда подходит к видимой части ближе чем на экран, в разрешении экрана (`devicePixelRatio`). Колесо и клавиши листают, `Esc` возвращает клавиши холсту, как в остальных окнах.
4. Байты PDF pdf.js получает из `Blob` файла, а не по `blob:`-адресу: CSP десктопа не пускает `fetch` по `blob:` (`connect-src`).
5. Файл, который pdf.js не открыл, — строка «PDF не открылся» в окне.
6. «Благодарности» перечисляют pdf.js и всё, что он поставляет.

## Альтернативы

- **Только фрейм, на Linux — открыть системой.** Было в предложении к Q-06-24. Окно на Linux вело бы себя иначе, чем на других ОС, а «Открыть системой» выносит пользователя из приложения.
- **pdf.js везде.** Один путь кода, но на Windows и macOS свой просмотрщик WebView быстрее, умеет поиск, выделение текста и печать без нашей работы.
- **PDFium в WASM** (Apache-2.0 и BSD-3-Clause). Сборок с поддержкой немного, размер больше, отрисовка текста — своя работа.
- **Отрисовка в ядре на Rust** (`pdfium-render`, `hayro`). Нужен PDFium рядом с бинарником или незрелый движок; в браузере — та же WASM-сборка.

## Последствия

- PDF открывается в окне на всех ОС; в WebKitGTK и браузерах без просмотрщика — без поиска и выделения текста (текстового слоя pdf.js пока нет).
- Сборка растёт на ~1,8 МБ кода (воркер и библиотека, грузятся лениво) и ~2,4 МБ файлов `pdfjs/`.
- e2e проверяют оба пути: фрейм — с `pdfViewerEnabled = true`, pdf.js — с `false` (страницы нарисованы, цвет пикселя, сломанный файл).
- Обновление `pdfjs-dist` — сверка списка файлов в `pdfAssets` и их лицензий.
