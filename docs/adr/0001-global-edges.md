# ADR-0001. Нити глобальны и связывают ноды, а не их размещения

- Статус: Принято (2026-10-19, по делегированию владельца)
- Дата: 2026-10-13
- Связано: [05-domain-model.md §8](../05-domain-model.md#8-нити-edge), [ADR-0002](0002-multi-placement.md), [13-interop.md](../13-interop.md); вопросы ☑ Q-05-5, ☑ Q-05-4, ☑ Q-13-3

## Контекст

- ✅ C3: одна и та же нода может использоваться в нескольких ветках.
- ✅ C4: нити — смысловые связи без типов; нода принимает сколько угодно входов.
- ✅ C8: ссылки `[[…]]` в тексте создают нити.
- 3D-карта показывает всё пространство сразу; AI через MCP отвечает на вопросы «что связано с X».
- ☑ Q-05-5 (раунд 2, 2026-10-19): нити глобальные — решение принято по делегированию владельца.

Если нода размещена в нескольких сетях, нужно решить, кому принадлежит нить: паре нод (глобально) или паре размещений внутри конкретной сети (локально, как в Houdini).

## Решение

Нить — это связь `from → to` между **нодами**. Она хранится в индексе пространства и рисуется в каждой сети, где размещены оба её конца. Документ сети хранит только оформление нити в этой сети: точки, стиль, ручной изгиб и флаг «скрыта здесь» ([05 §9.2](../05-domain-model.md#92-документ-сети-networkdoc)).

ID нити детерминирован (хеш пары `from → to`, считается от 16-байтовых ID нод), поэтому одновременное создание одной и той же нити двумя клиентами даёт одну нить. У нити к призраку ключ — хеш `from` и `?linkKey(X)`; при разрешении призрака нить пересоздаётся с новым ключом, а оформление в документах сетей переносится на него ([05 §8.1, §8.5](../05-domain-model.md#81-поля)).

## Альтернативы

1. **Локальные нити (как в Houdini).** Нить принадлежит сети и соединяет два размещения.
   - Плюс: правка в одной сети не влияет на другие.
   - Минус: ссылка `[[X]]` в тексте не знает, в какой сети рисовать нить; придётся заводить второй, глобальный тип связей — а типов связей мы не хотим (✅ C4).
   - Минус: 3D-карта и MCP должны объединять нити всех сетей, появляются дубликаты и противоречия («в одной сети связаны, в другой нет»).
2. **Гибрид:** глобальные связи из текста + локальные ручные нити. Отклонено: два вида нитей с разным поведением, которые выглядят одинаково, путают.

## Последствия

- ➕ Модель совпадает с Obsidian: импорт и зеркало Markdown честные.
- ➕ 3D-карта, поиск связей и MCP работают с одним графом.
- ➖ Вставка ноды в нить или встряхивание в одной сети меняют связь и в других сетях, где видны оба конца. Снижаем: встряхивание затрагивает только нити, видимые в текущей сети; при операции, задевающей нити, видимые и в других сетях, показываем ненавязчивое уведомление «Связь изменена ещё в 2 сетях» с отменой.
- ➖ Нужен значок «внешних связей» на бабле, чтобы связи с нодами вне текущей сети не терялись.
- ➖ Если в какой-то сети нить мешает, её можно скрыть только там (флаг в документе сети), но не удалить локально.
- ➖ Нить из ссылки `[[…]]` живёт, пока ссылка есть в тексте. ☑ Q-05-4: удаление такой нити на холсте спрашивает «Убрать ссылку из текста?» — «Убрать из текста» или «Скрыть нить в этой сети»; текст молча не меняется, групповой жест задаёт один общий вопрос в конце ([05 §8.2](../05-domain-model.md#82-правила) п. 5).
- ➖ В vault с тысячами ссылок нитей из текста много. ☑ Q-13-3: направление нитей не меняется, происхождения `text` и `manual` различаются; настройка сети «Нити из текста: все / приглушённые / скрыты» меняет только отображение, раскладка `L` строит дерево прежде всего по ручным нитям ([05 §8.3](../05-domain-model.md#83-нити-и-сети-что-видно-где)).
